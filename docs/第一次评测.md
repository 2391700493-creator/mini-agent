# 第一次评测

[文档导航](README.md)

评测就是让 Agent 回答一组固定问题，再按照你给出的标准检查回答。它能帮助发现问题；模型评分仍需结合人工判断。

## 先跑通一次

先在模型管理完成连接测试，再创建一个 Agent。初次尝试可使用提示词：“准确回答用户问题，遵守输出格式，不确定时说明。”

在 Agent 列表点击“评测”，目标 Agent 会自动选中。选择“基础能力示例”，再选择评分模型。评分模型负责检查回答，可与 Agent 使用同一个模型；这样方便起步，但并非独立人工判断。

保留默认的 60 分通过线，工具保持关闭，点击“开始评测”。这会真实调用模型回答三条问题，并调用评分模型检查结果。失败重试、上下文压缩等情况可能产生额外调用。

## 看懂结果

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| 通过 | 评分达到通过线，且过程规则未判定失败 | 检查是否覆盖真实任务，不能据此推断所有任务都可靠 |
| 未通过 | 回答或过程没有满足标准 | 展开用例，比较期望与实际回答，查看评分理由 |
| 执行失败 | Agent 未能完成回答 | 查看错误和运行详情，检查模型、权限与运行限制 |
| 评分失败 | 评分请求失败或返回内容无效 | 检查评分模型；不要直接当作 Agent 能力不合格 |

“确认 / 驳回”用于标记人工复核意见，不直接改写原始模型分数。单次分数存在波动。

## 换成自己的任务

在“数据集”中新建一组问题，每条填写“用户问题”，以及“期望答案”或“评分要求”。例如：

> 用户问题：把“周五前由小王整理反馈；上线日期待确认”整理成待办。
>
> 评分要求：保留负责人小王和周五前的期限；上线日期标为待确认；不得补充原文没有的信息。

先用几条真实问题检查评分标准是否清楚，再逐步补充信息缺失、格式约束和失败情况。历史消息、期望工具和耗时限制都在“历史消息与过程检查”中按需填写。

如果任务依赖文件或 MCP 工具，运行前确认绑定与启用状态，再勾选允许工具。工具会真实执行，可能读写文件或调用外部服务。

## 验证一次改进

从结果进入“调整 Agent”，修改提示词或能力配置后，用同一组问题、同一评分模型和通过线新建评测。比较变化时，同时查看失败内容、运行耗时和用量。保留原任务作为对照。

“仅重跑失败项”适合排查临时故障；配置变化后的验证应新建任务。当前没有并排实验对比或公开性能基准，示例通过率不能作为业务成功率。
