# Mini-Agent UI / UX 审查与本轮改版

审查日期：2026-09-14。范围：现有 Vue 页面、聊天交互、全局导航与首次使用路径。评分为设计审查判断，未进行真实用户研究。本轮直接改动聊天首页和全局导航，其余模块保留功能并纳入后续优先级。

## 结论

现有产品的技术能力已经超过界面表达：有模型配置、Agent 组合、工具执行、Skills、MCP 和运行记录，首页却只有导航、历史和输入框。最需要补齐的是“进入产品 → 知道能做什么 → 开始第一次对话 → 看懂和复用结果”的连续体验。

视觉上保留白色、浅灰、桃色和衬线标题，让 Mini-Agent 成为安静、有辨识度的个人 Agent 工作空间。大众产品值得借鉴的是主任务优先、能力就近呈现、复杂配置逐步展开。

## 对标依据及适用范围

[ChatGPT 当前公开页面](https://chatgpt.com/)可见新建聊天、聊天搜索、历史、设置和帮助，以及居中的任务问候。这里借鉴“开始对话”和“回到历史”的入口组织，不复制其品牌标志或会员功能。

[ChatGPT 文件与资料库说明](https://help.openai.com/en/articles/20001052-file-storage-and-library)说明文件从输入区的添加菜单进入。这支持把素材入口放在写消息的附近。本项目本轮提供的是文本读入草稿，尚无独立附件存储或资料库。

[DeepSeek 官方 App 介绍](https://api-docs.deepseek.com/news/news250115/)列出账号登录、跨端聊天记录、联网搜索、深度思考以及文件上传与文本提取。这是其 2025 年产品介绍，当前网页访问返回 403，未把它当作最新登录后布局的证据。这里参考功能发现方式，不声称已经实现相同的账号、多模态或推理能力。

## 原界面判断

没有明显的泛化 AI 视觉模板问题：未使用发光渐变、玻璃卡片和装饰性数据。优势在于配色统一、低干扰，以及已有的停止生成、错误提示、会话重命名和删除确认。主要短板是品牌过弱、入口缺乏分组和开始路径断裂。

| 优先级 | 问题与影响 | 具体调整 | 本轮状态 |
| --- | --- | --- | --- |
| P1 | 新用户没有 Agent 时只看到不可输入的聊天区，需要自己寻找模型与配置关系 | 明示连接模型 → 创建 Agent → 对话；已有 Agent 时自动准备空会话；提供任务示例 | 已做基础路径；逐步配置向导待做 |
| P1 | 工具、Skills、MCP 都在其他页面，聊天时不知道当前助手有什么能力 | 输入框上方就近查看当前 Agent 绑定、可用状态及模型，提供编辑入口 | 已做；不在此面板执行工具或扩展权限 |
| P1 | 长回复以纯文本展示，阅读和复用成本高 | 增加安全 Markdown 渲染、代码块、表格、复制回复；再做消息重试与编辑分支 | 下一轮优先 |
| P2 | 八个模块平铺，“聊天”和开发配置同等突出 | 分成工作空间、能力配置、观察与评测三组；保持原路由和八个入口 | 已做 |
| P2 | 单个字母标志、空白侧栏底部，缺少品牌归属和稳定的个人入口 | 统一 m 与圆点标志、favicon、品牌短句；底部锚定本地用户区 | 已做；账号登录尚未实现 |
| P2 | 历史只能浏览，素材只能粘贴 | 增加标题搜索；添加文本入口，导入前校验格式和大小，保留现有草稿 | 已做基础能力 |

## 本轮界面与交互

全局侧栏继续使用 188px。三组导航最多四项，底部用户入口独立固定，导航内容可滚动。899px 及以下使用带名称的 64px 窄栏，保留全部菜单和键盘入口。主导航可完全收起，切页保留当前收起状态。

聊天保持无可见页面标题。空会话用品牌标识、问候和一行说明建立阅读顺序；桌面问候保持 36px，小屏按既有字号变量缩放。浅灰输入区成为主要操作区，上方放文本导入和能力查看，下方展示三个任务示例。点击示例追加到草稿并聚焦输入，保留已有文字，不自动发送。

“添加文本”支持 UTF-8 TXT、MD、CSV、JSON，单文件最多 256 KiB；文件正文连同草稿最多 100,000 字符。文件名与原文进入草稿，可编辑后发送，未经发送不会提交模型。暂不支持 PDF、图片、拖拽、多文件附件生命周期和持久化资料库。模型自身上下文限制仍由后端检查。

“工具与技能”通过现有 Agent 详情接口获取配置。展示可用、停用或失效能力以及模型名称，并允许跳转修改配置。这里展示的是当前读取到的配置状态，执行时仍由 Runtime 再次校验。

底部“本地用户”显示本地使用说明、模型与 Agent 配置入口及键盘提示。会话和配置保存在本机；发送正文仍需调用用户配置的模型服务。此处没有虚构姓名、会员身份、登录或云端同步。

## 仍然最值得投入的内容

第一优先是回复阅读与复用。完成一次对话后，用户应能立即看懂段落、列表、表格和代码，并复制结果。Markdown 需要处理不可信内容和安全链接；复制应有结果提示。重试和编辑必须先定义历史分支、重复执行与工具副作用，避免误触重复执行。

第二优先是首次配置向导。把模型和 Agent 配置串成可返回的步骤，记住已完成步骤，展示测试结果和明确的下一步。测试真实服务可能产生费用，应沿用现有说明。目标是让第一次使用的人无需提前理解 MCP 和 Skills 就能完成普通对话。

第三优先是完整附件链路。引入 PDF 和图片前，需要定义模型能力检测、解析、进度、失败重试、移除、大小限制、消息关联及清理规则。只增加一个回形针不能完成这条路径。本轮文本导入用于满足轻量材料输入。

第四优先是工作区效率。会话全文检索、按日期分组、导出、可收起的历史栏和全局快捷键可以逐步加入。当前标题搜索不检索正文。对于管理页，先加入搜索、按启用状态筛选和紧凑列表；表单高级项按使用频率折叠，保存时保留错误定位和输入。

多用户账号、云端同步、团队空间属于后续产品范围。它们需要身份认证、数据归属、隔离和同步冲突处理。当前先把本地用户入口和个人工作空间表达完整。

## 各模块的下一步

| 页面 | 最需要调整的内容 | 验收条件 |
| --- | --- | --- |
| 聊天 | 安全 Markdown、复制回复、回复失败后的明确操作 | 代码和表格可阅读、复制结果有反馈，失败不丢正文 |
| Agent | 列表提供清楚的用途和“开始对话”；基础与高级配置分层 | 新用户能从创建顺畅进入与该 Agent 的对话 |
| 模型 | 常见兼容服务填写示例、连接结果和错误下一步 | 不隐藏 Base URL 与协议差异，不虚构可用模型 |
| 工具 / Skills / MCP | 搜索、启用筛选；状态旁解释失效原因 | 配置数量增多后仍能迅速找到可用能力 |
| 运行记录 | 先呈现结果与失败原因，再展开轮次和调用详情 | 能从聊天定位对应运行；已有记录功能继续复用 |
| 评测 | 明确未开放状态与准备条件 | 不把占位页包装为可执行功能 |

## 启发式评分（改版前）

0–4 分，4 为优秀；这份评分评估交互成熟度，不是生产质量认证。

| 维度 | 分数 | 主要依据 |
| --- | --- | --- |
| 系统状态可见 | 3 | 有流式、保存、失败及取消反馈 |
| 符合用户理解 | 2 | 模型、Agent 和能力配置的关系需要自行理解 |
| 用户控制 | 3 | 有停止、返回和删除确认，缺少回复级编辑与重试 |
| 一致性 | 3 | 颜色、间距与主要操作基本统一 |
| 错误预防 | 3 | 删除确认、输入校验及配置引用保护已具备 |
| 识别优于回忆 | 2 | 当前助手的能力需要离开聊天查找 |
| 操作效率 | 2 | 缺少历史检索、复制回复和素材入口 |
| 简洁与层级 | 3 | 界面安静，但导航权重过于接近 |
| 错误恢复 | 2 | 可重新加载，回复级恢复仍不足 |
| 帮助与引导 | 1 | 缺少持续可见的个人入口和具体开始示例 |
| 合计 | 24/40 | 基础可用，面向新用户的路径仍需完善 |

认知负担八项检查中，“分块、相关内容归组、避免跨页记忆、逐步展开复杂度”存在不足，计 4/8。单一主任务、输入优先级、顺序操作和发送决策相对清楚。这里只用作设计检查，不能据此推算用户流失率。

## 角色走查

首次学习 Agent 的用户：原首页只有“先创建 Agent”的提示，缺少接入模型的前置关系。本轮补上路径和两个管理入口；仍需要下一轮向导减少跨页来回。

每天使用的开发者：原会话记录不可检索，回复中的 Markdown 源码和代码不易复用。本轮补上标题搜索和能力查看；安全 Markdown 和复制回复应最先继续。

小屏和键盘用户：侧栏与会话栏共同占用空间，弹窗焦点容易迷失。当前保留窄栏名称、上下会话布局、主导航收起和原生 dialog；需继续关注长历史下到达输入框的操作距离。

## 建议的后续设计执行顺序

先用 `onboard` 完善首次配置和第一次对话，接着用 `typeset` 改善回复阅读，再用 `harden` 处理附件和失败恢复，最后用 `polish` 做跨页面一致性收尾。可按上述具体范围继续，不需要重新确定品牌方向。

## 验证与交付边界

本轮前端测试和生产构建均通过。新增测试覆盖文件格式、UTF-8、空内容、字节和字符边界、会话搜索、示例保留草稿，以及已有 Agent 时准备空会话。浏览器写入验收仅使用独立临时数据库、Skills、工具目录和测试主密钥；测试助手未连接真实模型，不代表真实模型调用验收。

本次没有变更数据库结构或后端业务逻辑。桌面与移动端预览、导航和焦点的浏览器结果见交付说明。

浏览器已验证 1440、899、390px 三种宽度下的八个菜单切换、直接访问、刷新和整页横向溢出检查。工具能力面板读取到临时助手的真实绑定；Escape 关闭后焦点返回入口。任务示例与文本导入保留原草稿且不发送。关闭临时后端后显示离线原因，重新启动并点击“重新加载”后恢复。
