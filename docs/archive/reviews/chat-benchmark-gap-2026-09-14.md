# Mini-Agent 界面对标梳理：差距清单与验收标准

梳理日期：2026-09-14。范围：现有前端全部页面与后端聊天/运行接口（逐条对照代码核实，不是印象判断）。本文只做梳理，不改任何代码。

## 对标基线

| 对标对象 | 作为标准的部分 |
| --- | --- |
| ChatGPT 网页版 | 输入框边缘的「+」增强菜单与工具下拉、消息悬停操作条（复制/重新生成/反馈/朗读）、编辑提问、会话搜索/归档/分享、空态聚焦、资料库 |
| DeepSeek 网页版 | 输入框下方一排能力开关（深度思考/联网搜索/附件）、附件上传（多文件、PDF/Office/图片）、思考过程折叠、回复复制与重新生成 |
| 腾讯 WorkBuddy | 输入框左侧「+」菜单（模式/模型/工作空间/技能/连接器/权限）、拖拽文件成卡片且不自动发送、超长粘贴折叠为 Chip、斜杠命令、每条回复显示耗时、多任务并行 |
| GitHub 事实标准 | open-webui（Markdown/LaTeX、分叉、文件夹标签、导出导入、消息队列、追问建议、快捷键、`/`「@」「$」触发符）、lobe-chat、NextChat（ChatGPT-Next-Web，全程 Markdown+LaTeX、编辑重发与分支、导出）、LibreChat（消息搜索、编辑重发、分支、导出）、Vercel AI Chatbot（流式 Markdown 渲染、Artifacts） |

这些产品共同收敛出的经典形态：**输入框是唯一主操作区，增强能力收进输入框边缘的菜单；回复必须富文本可读、可复制、可重试、可追问；历史可分组、可检索；配置页只做管理，聊天页就近完成一切对话操作。**

阅读说明：每条给出「要增加/调整什么 → 现状 → 为什么（对标与验收）」。标【后端】的需要新增接口，其余为前端改造。优先级见文末。

## 一、聊天输入区（Composer）——差距最集中，优先做

### 1. 把增强能力收进输入框边缘的「+」菜单（用户点名项）
- **现状**：输入框**上方**平铺两个独立按钮「添加文本」「工具与技能」，与输入框是分离的两行；能力查看是弹窗，没有开关；没有模式/快捷指令入口。
- **为什么**：ChatGPT 的附件/工具入口在输入框左下角「+」菜单（从电脑添加、从资料库添加、工具下拉）；DeepSeek 的能力开关紧贴输入框下沿；WorkBuddy 在输入框左侧「+」菜单里统一收纳模式、模型、技能、连接器、权限。**验收**：输入框左下角一个「+」按钮，弹出分组菜单（添加文件、能力查看/快捷开关、模式/指令）；现有「工具与技能」弹窗并入该菜单；菜单支持 Esc 关闭与键盘选择；空态和有消息时位置一致。

### 2. 附件改为 Chip/卡片，不再把文件内容拼进草稿
- **现状**：「添加文本」读取 TXT/MD/CSV/JSON 后，把「文件名 + 全文」直接写进 textarea 草稿；没有文件卡片、没有移除入口、没有解析状态，想去掉只能手动删文本。
- **为什么**：ChatGPT/DeepSeek/WorkBuddy 的附件都是输入框上方的文件卡片（图标、文件名、状态、× 移除），**添加后不自动发送**，可继续补文字。**验收**：导入后在输入框上方出现文件 Chip（名称、大小、移除 ×、失败状态），正文不被文件全文占满；移除 Chip 不影响草稿文字；未发送前可删除；超限/格式错误在 Chip 上提示。

### 3. 支持拖拽添加文件、点击区域容错
- **现状**：只能点按钮选文件，不支持拖拽。
- **为什么**：WorkBuddy 拖到页面任意位置出现「松开即可添加文件」提示层，拖出或 Esc 取消；open-webui 支持拖拽导入。**验收**：拖拽文件到聊天区出现提示层，松开生成附件 Chip；非法文件给明确错误；Esc 取消且不污染草稿。

### 4. 超长粘贴自动折叠为 Chip
- **现状**：粘贴多长都直接堆在 textarea 里（上限 100,000 字符），输入区被长文撑满。
- **为什么**：WorkBuddy 粘贴超 3,000 字符自动压缩为 Chip，悬停预览、点击展开回输入框编辑。**验收**：超长粘贴折叠为可展开/移除的 Chip，短粘贴保持原样。

### 5. 生成中可以继续打字（消息队列）
- **现状**：生成期间 textarea 被禁用，必须等回复结束才能输入下一条。
- **为什么**：ChatGPT 生成时可继续输入；open-webui 有 Message queue，回复期间打字、完成后自动发送。**验收**：生成中输入框可用，已写内容保留；提供「排队发送」或在完成后自动发送，停止生成不丢草稿。

### 6. 输入框随内容自动增高
- **现状**：固定 2 行，靠手动拖拽（`resize: vertical`，最高 180px）。
- **为什么**：经典产品输入框均按内容自动增高、到上限再内部滚动。**验收**：输入自动增高，达到上限（建议 200px 左右）后出现滚动条；发送后恢复单行高度。

### 7. 输入框附近的会话级开关（对标深度思考/模式切换）
- **现状**：是否允许工具执行、是否自动压缩等只能在 Agent 编辑页修改，聊天时无法临时切换；Agent 选择是输入框左下一个裸 select。
- **为什么**：DeepSeek 输入框下沿有「深度思考/联网搜索」开关；WorkBuddy「+」菜单里有 Agent/Plan/Ask 三种模式，开启后输入框下方显示模式标识、点 × 退出。**验收**：输入框下沿放当前 Agent 名（保留 select）+ 可即时切换的会话级开关（如「允许工具执行」「自动压缩」），开关状态只影响当前会话并有可见标识。【后端：会话级覆盖参数】

### 8. 斜杠命令与提及（/、@）
- **现状**：无。
- **为什么**：open-webui 输入 `/` 出命令（如 `/compact` 立即压缩、`/status` 看上下文用量）、`@` 切模型/附文件、`$` 提及技能；WorkBuddy 有斜杠命令补全。**验收（可分期）**：一期 `/` 提供「新建会话、立即压缩上下文、清空输入」等本地命令；二期 `@` 快速切换 Agent、`#` 引用已绑定 Skill；命令不会被当作正文发送。

### 9. 输入容量与字数提示
- **现状**：只有 100,000 字符硬上限，无计数；上下文容量事件藏在消息区一个折叠 details 里。
- **为什么**：open-webui `/status` 显示上下文用量；经典产品在接近上限时给即时提示。**验收**：输入框右下角显示字符数（接近上限时显性化）；后端已有的上下文估算结果在输入区附近以轻量进度/文案提示「预计接近上下文容量」。

### 10. 语音输入（后置）
- **现状**：无。
- **为什么**：ChatGPT App、open-webui 均有语音输入/朗读。本地桌面产品列为 P3，菜单里预留位置即可。

## 二、消息流与回复呈现

### 1. Markdown 渲染 + 代码高亮 + 代码块复制（P0，最影响阅读）
- **现状**：助手回复是纯文本（`white-space: pre-wrap` 直接输出原文），标题、列表、表格、代码块全部显示 Markdown 源码；运行详情页的最终回答同样是纯文本。
- **为什么**：ChatGPT/DeepSeek/NextChat/open-webui/LibreChat 全部默认富文本渲染（open-webui 为 Full Markdown + LaTeX；Vercel 样板用流式 Markdown 渲染器）。**验收**：流式过程中增量、安全渲染标题/列表/表格/引用/代码块/链接/粗体斜体/分隔线；代码块带语言标签、右上角「复制」按钮且复制有反馈；链接安全（新窗口、`rel="noopener"`，禁内联脚本/事件）；未信任内容做 XSS 过滤；运行详情最终回答复用同一渲染组件。

### 2. 消息悬停操作条：复制 / 重新生成 / 重试 / 反馈
- **现状**：消息上没有任何操作按钮；回复失败只有页面级「重新加载」，成功回复无法再来一次。
- **为什么**：ChatGPT、DeepSeek 每条助手回复下方都有复制、重新生成（赞/踩、朗读）；open-webui 同类标配。**验收**：助手消息下方悬停（移动端常显）出现操作条：复制（带「已复制」轻反馈）、重新生成、失败时为重试；操作条不干扰正文选择；需要全局 Toast 轻提示组件（现状只有行内 notice）。

### 3. 重新生成回复【后端】
- **现状**：后端无 regenerate 接口（只有发送、停止、改会话、删除）；前端无入口。
- **为什么**：对标产品每条回复可重新生成。**验收**：对最后一条助手回复可重新请求；重新生成期间复用现有流式与停止能力；明确工具副作用策略（工具类重新执行需提示或可跳过）；新回复与旧回复的替换/留存规则清晰（建议先替换、分支后置）。

### 4. 编辑已发送的用户消息并重发【后端】
- **现状**：用户消息发出后不可改，只能重打一遍。
- **为什么**：ChatGPT 可编辑最近提问重发；NextChat/LibreChat 支持编辑、重新提交并做会话分支；open-webui 支持分叉（Fork）。**验收（一期）**：最后一条用户消息可就地编辑、回车重发，重发后其后的助手回复重新生成；**二期**：任意消息分叉为新会话（Fork），原会话不动。

### 5. 回复元信息：模型 · 耗时 · Token
- **现状**：这些数据运行记录里都有（模型快照、duration、usage），但聊天页完全不显示；只有工具卡片自带耗时。
- **为什么**：WorkBuddy 每条回复实时计时、完成后定格；open-webui 消息下方有 meta 区。**验收**：助手消息下方一行灰色 meta（Agent/模型名 · 耗时 · Token 用量，数据缺失显示「—」），与操作条合并排版，不抢眼。

### 6. 「思考/执行过程」分层折叠
- **现状**：工具调用已有可折叠卡片（保留，做得对）；但模型轮次、压缩、整体进度散落在「正在思考…」状态行和一个技术性 details 里，用户看不出「这一轮做了什么」。
- **为什么**：DeepSeek「深度思考」、ChatGPT thinking、open-webui 推理块都是与正文分离的可折叠过程区。**验收**：每次生成在正文上方显示一个可折叠的「执行过程」区（第 N 轮模型、调用了哪些工具、是否压缩上下文），完成后默认收起；工具卡片嵌在其中；正文与过程视觉层级明确分开。

### 7. 回复后的追问建议
- **现状**：只有空态有 3 个固定示例，回复完成后没有后续问题建议。
- **为什么**：open-webui 在回复后自动生成追问 chips；ChatGPT 有后续建议。**验收**：回复完成后给出 2–3 个可点击追问（点击填入输入框或直接发送，行为与空态示例一致：先入草稿、不自动发送）。

### 8. 消息按日期分隔
- **现状**：消息连续排列，跨天对话没有日期分隔线。
- **验收**：日期变化处插入浅色分隔（今天/昨天/日期），不打断阅读。

### 9. 选中文字的浮层操作（后置）
- **现状**：无。
- **为什么**：成熟产品选中回复文字弹出复制/引用。P3，可在消息操作条稳定后再做。

### 10. 会话导出 / 分享（本地版做导出）
- **现状**：无导出、无分享；会话只能在本机界面内看。
- **为什么**：ChatGPT 分享链接；open-webui 可导出单个/全部会话为 JSON/PDF/Markdown；NextChat/LibreChat 导出 Markdown/截图。**验收（一期）**：会话菜单提供「导出为 Markdown」（含时间、角色、工具摘要），纯前端由会话详情生成即可；PDF/批量导出 P3。

## 三、会话列表与历史管理

### 1. 历史按日期分组
- **现状**：会话按置顶 + 更新时间平铺，一长条。
- **为什么**：ChatGPT、DeepSeek 侧栏均按「今天 / 昨天 / 近 7 天 / 更早」分组。**验收**：分组标题浅色小字，置顶组独立在最上；组内保持现有排序。

### 2. 搜索从「仅标题」升级为全文检索【后端】
- **现状**：搜索框只匹配会话标题。
- **为什么**：ChatGPT 网页版侧栏可搜聊天记录；open-webui 历史搜索覆盖正文。**验收**：搜索命中消息正文，结果带命中片段与会话标题；空结果文案保留；后端增加正文查询。

### 3. 会话悬停预览
- **现状**：只能看到标题和时间。
- **为什么**：open-webui 悬停会话弹出最新消息缩略预览，不用打开即可辨认。**验收**：悬停 0.3s 后出现浮层显示最后一条消息摘要，移开即关，键盘焦点不触发。

### 4. 批量管理（多选置顶/删除）
- **现状**：置顶、重命名、删除都要逐条开「···」菜单。
- **验收**：列表提供「多选」模式，可批量删除/置顶；删除仍走确认；有全选与当前选中计数。

### 5. 归档 / 文件夹 / 标签（后置）
- **现状**：只有置顶。
- **为什么**：ChatGPT 有归档；open-webui 有文件夹、标签、置顶。**验收（P3）**：先做归档（不出现在默认列表、可恢复）；文件夹/标签待会话量上来后再做。

### 6. 列表交互效率微调
- **现状**：重命名必须开菜单选「重命名」再开对话框；无快捷键入口新建会话。
- **验收**：悬停行内直接显示「···」（现状常显三个点，可改为悬停显现，降低视觉噪声）；支持双击标题重命名；提供「新建会话」全局快捷键（见六-1）。

### 7. 自动标题质量（后置）
- **现状**：取首条用户消息前 30 个字符做标题（可用但口语化、常带文件名前缀）。
- **为什么**：ChatGPT/DeepSeek 由模型生成简短标题。**验收（P3）**：首轮完成后异步生成 10–20 字标题，手动命名过的会话不覆盖；失败保留现状规则。【后端】

## 四、聊天页头部与上下文

### 1. 增加轻量会话标题栏
- **现状**：聊天页无可见标题栏（只有无障碍隐藏标题），当前会话名只出现在左侧窄栏；重命名、删除都要去左栏菜单。
- **为什么**：ChatGPT/DeepSeek/WorkBuddy 对话区顶部都有会话标题与操作入口。**验收**：消息区顶部一行：会话标题（点击可改名）、当前 Agent · 模型名、右侧「更多」菜单（重命名、导出、查看运行记录、删除）；窄屏收为图标；保持现有「聊天页无大标题」的安静风格，标题栏视觉要轻。

### 2. 当前模型在聊天页可见
- **现状**：只看得到 Agent 名（输入框左下 select），模型名要打开「工具与技能」弹窗或去管理页看。
- **为什么**：ChatGPT 顶部是模型选择器；用户需要知道「这句话发给谁」。**验收**：标题栏或 Agent 选择器旁显示模型名（只读），切换 Agent 时联动更新。

### 3. 聊天 ↔ 运行记录双向跳转【后端小改】
- **现状**：运行列表接口已带 `conversation_id`，但运行页不能按会话筛选，聊天页也没有入口跳运行；助手消息无法定位到对应运行。
- **为什么**：旧一轮审查也把它列为待办；定位「那次回复为什么调了工具」是 Agent 产品的高频路径。**验收**：助手消息 meta 或会话菜单提供「查看运行记录」，跳到运行页并自动按当前会话过滤；运行详情可返回对应会话。

### 4. 「工具与技能」能力面板保留并归位
- **现状**：弹窗展示当前 Agent 绑定的工具/Skills/MCP 及可用状态，可跳编辑页（内容保留）。
- **验收**：并入「+」菜单的「能力」分组；展示内容不变，继续保持「只查看、执行时 Runtime 再校验」的边界。

## 五、空状态与首次使用

### 1. 空状态降噪：只留一句问候 + 输入框 + 示例
- **现状**：空态有品牌行、衬线大问候「你好，我们要聊些什么？」、副文案「从一个想法开始，与你的 Agent 一起完成。」、输入框下方提示「新建会话，或从左侧继续上次的对话。」、最底部「会话保存在本机 · 内容发送至所选模型服务」，加上打字机占位符「今天有什么想聊的？」——同屏 5 处说明性文字。
- **为什么**：ChatGPT 空态只有一句问候 + 居中输入框 + 少量示例；DeepSeek 空态即输入框与能力按钮。**验收**：空态保留 1 句问候、输入框、最多 3 个示例；删除副文案、start-hint、底部本地说明（本地/发送说明挪到「本地用户」弹窗，那里已有同类内容）；打字机占位符改为静态短句或直接去掉。

### 2. 首次配置分步向导
- **现状**：没有 Agent 时只有一张桃色卡「连接模型 → 创建 Agent → 开始对话」加两个链接，用户要在模型页、Agent 页之间自己摸索，不知道走到哪一步。
- **为什么**：WorkBuddy 提供十分钟上手路径；ChatGPT 新用户有连续引导。**验收**：向导分 3 步（添加模型并测试通过 → 创建 Agent（可一键用默认值生成）→ 发送第一条消息），记住每步完成状态，每步内联完成而不是只给链接，全部完成后引导消失；有 Agent 的老用户不再出现。

### 3. 示例点击行为保持
- **现状**：点示例追加到草稿并聚焦、不自动发送、保留原草稿（符合「不自动发送」标准，保留）。

## 六、全局导航、设置与效率

### 1. 全局快捷键 + 快捷键说明面板
- **现状**：只有 Enter 发送 / Shift+Enter 换行（还在输入区和「本地用户」弹窗重复写了两遍）。
- **为什么**：open-webui 有可重绑定快捷键设置；ChatGPT 有新建会话、聚焦输入等快捷键。**验收**：至少提供：新建会话、聚焦输入框、聚焦会话搜索、切换上/下会话；「本地用户」弹窗里列出快捷键表；输入区不再常驻键盘提示（或仅空态显示一次）。

### 2. 统一设置页
- **现状**：没有设置入口；时区、数据库路径等靠环境变量，界面偏好无处可放。
- **为什么**：经典产品均有 Settings。**验收**：新增「设置」（放侧栏底部用户区弹窗内或独立页）：外观、聊天偏好（自动滚动、示例开关）、数据管理（数据库位置展示、导出全部、清空会话）、快捷键表；只读项明确标注。

### 3. 暗色模式（后置）
- **现状**：tokens.css 只有一套浅色变量，无暗色。
- **为什么**：ChatGPT/DeepSeek/open-webui 均提供深色。**验收（P3）**：颜色全部走 tokens 变量（现状基础好），补一套暗色变量与切换开关，跟随系统/手动/浅色三态。

### 4. 命令面板（后置）
- **现状**：无。
- **验收（P3）**：⌘K / Ctrl+K 打开：跳转八个模块、新建会话、切换 Agent、搜索会话。

### 5. 全局 Toast 轻提示
- **现状**：所有反馈都是行内 notice 或卡片内文字，位置不统一、停留要手动消失。
- **验收**：复制、启停、保存、导入结果统一走右下角 Toast，2–3 秒自动消失，不阻断操作；错误类保留现有 role="alert" 区域。

### 6. 侧栏底部用户区精简
- **现状**：「本地用户 / 个人工作空间」弹窗内含连接模型、配置 Agent 两个链接 + 键盘提示 + 版本字样，与空态、输入区文案重复。
- **验收**：弹窗只保留：本地使用说明一句、设置入口、快捷键表入口；删除与首屏重复的操作引导（向导上线后由向导承接）。

## 七、文案审计（用户点名「很多无用文案」）

原则：**标题说「是什么」，不写口号；每个区域最多留一条必要说明；状态描述必须与真实功能一致。**

| 位置 | 现状文案（示例） | 处理 |
| --- | --- | --- |
| Agent 管理页脚 | 「聊天已支持模型直接回答，工具与能力执行暂未开放。」 | **必须删改**：与现状不符，工具/Skills/MCP 已通过 Runtime 在聊天中执行，属于过时错误信息 |
| 路由模块定义 `modules.ts` | 八个模块各有 headline/introduction/next/focus 四组抒情文案，如「给你的想法，一个回应。」「让每个 Agent，都有明确的任务。」「好的方法，值得重复使用。」 | 占位页与空状态统一改为「还没有 X + 一句功能说明 + 主按钮」，删除口号式 headline；评测等未开放模块只保留「未开放 + 准备条件」 |
| 各管理页空状态 | 「明确任务，配好能力。」「把方法写下来，留给下一次任务。」「一次运行，一条完整轨迹。」「从一个本机 Server 开始。」 | 统一为功能性标题（如「还没有 Agent」「还没有 Skill」）+ 一句说明 + 主按钮 |
| 主导航品牌下 | 「让想法，走到下一步。」 | 删除或仅保留在关于/设置中，侧栏不再占用一行 |
| 聊天空态 | 「从一个想法开始，与你的 Agent 一起完成。」「新建会话，或从左侧继续上次的对话。」「会话保存在本机 · 内容发送至所选模型服务」 | 按五-1 删减，本地说明并入用户弹窗 |
| 输入区 | 常驻「Enter 发送 · Shift+Enter 换行」；「添加文本」按钮 title 写了整句格式与大小说明 | 键盘提示移入快捷键表；格式/大小说明收进「+」菜单的 tooltip 与错误提示 |
| 每页页脚 `page-footer` | 每个管理页底部一句注释（「密钥加密保存在本机…」「启停状态保存在本机…」等 7 处） | 与表单 hint 重复的删除；涉及安全边界的保留为字段旁提示，每页最多一条 |
| 占位页（评测） | 与已开放模块同样的营销大标题 +「待开发」标签并列，容易误判已可用 | 明确「尚未开放」状态、准备条件、预计依赖，不使用营销模板 |
| 打字机占位符 | 「今天有什么想聊的？」逐字动画 | 改静态文案或移除（遵循减少动态效果的系统设置） |

## 八、能力配置模块（Agent / 模型 / 工具 / Skills / MCP）

### 1. Agent 管理
1. **列表补搜索与「开始对话」**：现状卡片无搜索、无直接开聊入口，建完 Agent 要手动回聊天页再选中它。验收：列表顶部搜索框；每张卡片有「开始对话」，点击后新建会话并复用现有「选择 Agent」接口（PUT .../agent）自动选中该 Agent，再进入聊天。
2. **表单高级项折叠**：现状「上下文容量」4 个压缩参数（触发比例/保留轮数/摘要目标长度/开关）与名称、模型同层平铺，普通用户用不到。验收：收进「高级设置」折叠区，默认值保持现状；基础区只留名称、说明、模型、最大轮数。
3. **复制 Agent / 保存后试聊**：现状无复制；保存后跳回列表。验收：卡片菜单加「复制配置」；表单保存成功页提供「保存并试聊」。
4. **系统提示词模板**：现状空白 textarea 从零写。验收：提供 2–3 个内置模板骨架（可一键填入再改）。
5. **列表信息密度**：现状每张卡 4 项计数 + 更新时间 + 3 个按钮，数量多后偏长；验收：紧凑行视图与卡片视图二选一固定（建议紧凑列表 + 行展开详情）。

### 2. 模型管理
1. **常见服务商预设**：现状 base_url、model_id 全靠手填，填错 /v1 是高频错误（表单里已在写提示兜底）。验收：新增模型时可选预设（DeepSeek、OpenAI、智谱、Kimi、通义、本地 Ollama/vLLM 等），自动带出 base_url 格式与文档链接、常见模型标识下拉，仍允许自定义。
2. **模型能力标记**：现状不记录模型是否支持视觉、工具调用、推理模式；这是后续图片附件、思考开关的前置。验收：模型表单增加能力勾选（仅记录与前端开关联动，不替模型宣称能力）。
3. **列表搜索 + 测试状态常驻**：现状无搜索；测试结果只在点击后出现，刷新即失。验收：搜索框；卡片上显示「最近一次测试：成功/失败/未测试 + 时间」。

### 3. 工具管理
1. **工具试运行**：详情页只有静态 JSON 示例并标注「尚未执行」；后端 `POST /api/tools/{id}/execute` 已存在，前端没有试跑表单。验收：详情页提供参数表单（按 input_schema 生成），执行后展示统一 ToolResult，危险操作沿用现有沙箱与授权目录限制，测试只操作临时文件。
2. **引用关系展示**：现状删除时后端做引用检查，但列表/详情看不到「哪些 Agent 在用」。验收：工具详情显示绑定它的 Agent 名单（Skills、MCP 同样补齐）。
3. 现状仅 3 个内置工具，搜索/筛选暂不需要；自定义工具上线后再补。

### 4. Skills 管理
1. **补「新建 Skill」入口**：现状只能导入 ZIP 或手动去 `workspace/skills` 建目录；编辑页 `SkillFormPage` 已存在，但路由只有 `:id/edit`，没有新建路由和按钮。验收：列表页加「新建 Skill」，在线填写 name/description/正文后原子写入目录，与 ZIP 导入走同一套校验。
2. **列表搜索 + 启用筛选**：现状无。验收：名称搜索、全部/已启用/已停用/有问题筛选。
3. **正文预览**：现状编辑页是纯 textarea。验收：编辑态支持「预览 Markdown」切换。

### 5. MCP 管理
1. **搜索与状态筛选**：现状无，Server 增多后难管理。验收：同 Skills。
2. **常见 Server 配置预设/模板**：现状命令、参数全手填。验收：提供常见本机 Server 的配置模板（仅填命令模板与说明，不自动安装程序）。
3. **引用关系**：同工具 3.2。

### 6. 管理页统一规范
- 所有列表统一：顶部搜索 + 状态筛选 + 右侧主操作按钮；空态统一文案结构；卡片操作按钮顺序统一（主操作在右、删除为纯文本按钮，现状已基本一致，保持）。

## 九、观察与评测

### 1. 运行记录按会话过滤与搜索【后端小改】
- **现状**：只能按状态、Agent 筛选 + 分页；接口已有 `conversation_id` 字段但没有过滤参数，也无关键词/时间范围筛选。
- **验收**：支持按会话过滤（承接四-3 跳转）、时间范围、错误关键词搜索。

### 2. 运行详情的最终回答用 Markdown
- 现状为纯文本 `<pre>`/纯文本段落；验收：复用聊天的 Markdown 渲染组件。

### 3. 失败运行的恢复入口
- **现状**：失败只显示错误摘要与时间线，没有后续动作。
- **验收**：失败运行详情提供「回到会话继续」「复制错误信息」；权限/参数被拒绝的步骤明确标注未执行（现状时间线已有该文案，保留并前置到摘要区）。

### 4. 用量汇总视图（后置）
- **现状**：观察分组只有明细列表，没有任何汇总；模型价格字段已采集但无处使用。
- **验收（P3）**：按天/Agent/模型汇总调用次数、Token、估算成本（价格缺失时明确标注「未配置价格」）。

### 5. Agent 评测占位页如实标注
- **现状**：评测页用通用营销占位模板（「让每次改进，都有据可依。」+ 待开发卡片）。
- **验收**：明确「尚未开放」、开放前需要具备的条件（可运行 Agent、测试用例格式）、与运行记录的关系；不伪装成可用功能。

## 十、附件与多模态路线（划清边界，防止只做半个链路）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 一期（本次清单内） | 「+」菜单、文本文件 Chip 化、拖拽、多文件、移除与状态、超长粘贴 Chip | 文件不进正文、不自动发送、可移除；格式/大小/编码错误有明确提示；沿用 256 KiB 与 100,000 字符上限 |
| 二期 | PDF / Word / Excel / PPT / 图片附件（DeepSeek 支持最多 50 个、单文件 100MB；ChatGPT 有资料库） | 上线前必须先定义：模型能力标记（八-2.2）、解析方案与进度、失败重试、大小与数量限制、附件与消息的关联、清理规则；只加一个回形针不算完成 |
| 三期（P3） | 资料库（已上传文件复用，ChatGPT Library）、图片消息渲染、语音 | 依赖多模态模型能力，不提前承诺 |

明确不在当前阶段范围：账号体系、云同步、团队空间、联网搜索本身（联网能力未来通过 MCP/工具接入后，在「+」菜单以开关呈现）、图像生成。

## 十一、验收总清单（达到经典产品形态的勾验项）

**输入区**
- [ ] 输入框左下角「+」菜单统一收纳附件、能力、模式/指令
- [ ] 附件以 Chip 展示、可移除、不自动发送；支持拖拽；超长粘贴折叠
- [ ] 生成中可继续打字；输入框自动增高
- [ ] 当前 Agent/模型在输入区或标题栏可见；会话级开关就近可用
- [ ] 斜杠命令（至少本地命令）可用

**消息**
- [ ] 回复为安全 Markdown：表格/列表/标题/代码块正确，代码块可复制且有反馈，LaTeX 二期
- [ ] 每条助手回复有操作条：复制、重新生成/重试
- [ ] 用户消息可编辑重发（一期最后一条，二期任意位置分叉）
- [ ] 回复下显示模型 · 耗时 · Token；执行过程可折叠且默认收起
- [ ] 回复完成后有追问 chips；跨天有日期分隔
- [ ] 失败消息有单条级重试，不再只有整页重新加载

**历史与头部**
- [ ] 会话按日期分组；搜索覆盖正文；悬停可预览；可批量管理
- [ ] 聊天区有轻量标题栏（改名/导出/运行记录/删除）
- [ ] 聊天与运行记录可双向跳转；会话可导出 Markdown

**空态与引导**
- [ ] 空态只剩一句问候 + 输入框 + ≤3 示例
- [ ] 无模型/无 Agent 时是分步向导，步骤状态可见、可内联完成

**配置与观察**
- [ ] Agent 列表可搜索、可一键开聊、高级参数折叠、可复制
- [ ] 模型有服务商预设、能力标记、最近测试状态
- [ ] 工具可试运行；Skills 可在线新建；MCP/Skills 列表可搜索筛选；能力详情显示引用的 Agent
- [ ] 运行记录可按会话过滤；最终回答 Markdown；评测占位如实标注

**全局与文案**
- [ ] 全局快捷键 + 快捷键表；统一设置页；统一 Toast
- [ ] 过时错误文案（Agent 页脚）删除；营销口号按第七节清单收敛，每区域最多一条说明

## 十二、优先级建议

| 优先级 | 内容 |
| --- | --- |
| **P0（先做，决定「像不像成熟产品」）** | Markdown 渲染 + 代码块复制（二-1）；消息操作条 + 单条重试（二-2、二-5 的重试部分）；「+」增强菜单与附件 Chip 化、拖拽（一-1/2/3）；文案审计与过时错误文案删除（七） |
