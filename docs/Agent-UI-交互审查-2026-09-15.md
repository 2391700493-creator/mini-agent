# Mini-Agent Agent UI 与交互审查

日期：2026-09-15  
范围：聊天、Agent 管理、新建 Agent、运行记录、运行详情。  
目标：把产品从“配置管理界面”调整为“用户能放心完成任务的 Agent 工作台”。

## 参考的经典 Agent 交互原则

本审查没有建议复制某个竞品的视觉样式，只借鉴成熟 Agent 产品中反复出现的交互原则：

1. 聊天是完成任务的主场，配置是辅助流程。
2. Agent 执行时，用户应看见简短的计划、当前动作、工具结果和最终结果；不展示模型隐藏推理过程。
3. 有风险的工具应在“即将执行”时由用户确认，确认界面要说明影响范围。
4. 高级能力按需展开，首次创建 Agent 只要求完成最少的决定。
5. 失败信息必须给出直接、可执行的修复入口。

这与 Claude Code 的权限模式、工具允许/拒绝规则一致；其默认模式会在工具首次使用时请求确认。[Claude Code 权限说明](https://docs.anthropic.com/en/docs/claude-code/iam)  
OpenAgent 把逐步工具调用及结果作为可见能力，适合作为运行透明度的参考。[OpenAgent](https://github.com/the-open-agent/openagent)  
ChatGPT Agent 在需要登录时会暂停并让用户接管，说明 Agent 不能把高风险或需要身份的步骤悄悄做完。[ChatGPT Agent 说明](https://help.openai.com/en/articles/11752874-chatgpt-agent)

## 已查看的现状

- 聊天页：会话列表、输入区和 Agent 下拉框完整，但当前 Agent 不可用时，只显示“Agent 模型或系统提示词不可用，请检查配置。”，发送按钮同时禁用。
- 新建 Agent：按“任务与模型、上下文容量、系统提示词、能力绑定”纵向排布；每个高级上下文参数都在首次创建时出现。
- Agent 管理：卡片只显示模型、工具、Skills、MCP 数量，任务用途和可执行边界不突出。
- 运行记录：列表使用七列表格；失败运行可进入详情，但详情只复述错误，没有下一步操作。

以下建议以此为依据。P0 表示先做，P1 表示完成 P0 后做，P2 表示体验完善项。

## 待修改 1：把“Agent 不可用”改成可修复的就地状态

**优先级：P0**

当前聊天页中，用户看到错误文字后，输入、Agent 选择和发送都不可用；用户不知道是模型被删、Key 失效、系统提示词为空，还是 Agent 被停用。

调整为输入区上方的状态卡：

- 标题直接说明具体原因，例如“Deepseek-V4 的连接不可用”。
- 显示受影响的 Agent 和配置项。
- 提供一个主按钮“去检查模型”，次按钮“切换可用 Agent”。
- 若没有任何可用 Agent，主按钮改为“创建可用 Agent”，并给出 3 步进度：模型 → Agent → 开始对话。

不要只显示“请检查配置”。错误页的目标是让用户用一次点击回到可继续对话的状态。

## 待修改 2：聊天空状态改为“从任务开始”

**优先级：P0**

当前空聊天主要留下输入框。对于第一次使用者，产品没有回答“我可以让这个 Agent 做什么”。

在问候语下加入 3 个基于当前 Agent 的任务示例，例如：

- “分析这段关系中的沟通问题”
- “根据聊天记录列出待确认问题”
- “帮我把观点整理成行动建议”

点击示例只填入草稿并聚焦输入框，不自动发送。示例应随 Agent 的说明、Skill 和已启用工具变化；没有能力时显示“当前 Agent 只能对话，不会调用外部工具”。

## 待修改 3：重新组织输入框中的附件、能力与 Agent 选择

**优先级：P0**

当前“+”菜单同时包含“从电脑添加文件”“查看工具与技能”“清空输入”，功能性质混杂；当前 Agent 的能力又隐藏在菜单内。

建议：

- `+` 只负责添加内容：文本文件、粘贴内容。
- Agent 名称旁增加轻量“能力”按钮，弹层以标签显示可用 Skill、工具和 MCP 数量，并提供“查看详情”。
- Agent 下拉框保留在输入框底部，但显示名称 + 任务说明的短句，不只显示名称。
- 清空输入移到输入框获得内容后才出现的次级操作，不与上传并列。

这样用户在发送前能回答三个问题：我在和谁对话、它能做什么、这次会带入什么内容。

## 待修改 4：增加运行中的“任务进度条”，而非只在结束后留工具卡

**优先级：P0**

经典 Agent 界面会把工作过程压缩成用户可理解的状态，例如“正在分析问题”“正在调用文件工具”“等待你的确认”“正在整理结果”。

当前运行事件已经存在，应在聊天流中增加可折叠的进度块：

1. 接收任务
2. 正在处理 / 第 N 轮
3. 工具名称与一句用途
4. 完成、失败或等待确认

工具输入和原始结果默认折叠，只在用户点击后展开。不要展示思维链或“模型正在推理”等不可验证内容。生成期间将“停止生成”放在输入区主按钮位置，避免用户到页面其他位置寻找中止操作。

## 待修改 5：在工具真正执行前增加审批卡

**优先级：P0**

当前能力绑定决定 Agent 是否有工具权限，但用户在一次具体操作发生前看不到影响。对 Shell、文件写入和将来接入的外部 MCP，这不够安全，也不利于建立信任。

在聊天流中加入审批卡：

- 清楚说明“将要做什么”“影响哪个文件/服务”“是否会写入或联网”。
- 提供“本次允许”“本会话允许”“拒绝”三个动作。
- 只读工具可按 Agent 配置自动执行；写入、Shell、外部服务默认需要确认。
- 被拒绝后，Agent 收到结构化结果并继续给出替代方案。

审批不是一个通用弹窗。它应出现在对应工具步骤的位置，使用户能把授权和任务上下文关联起来。

## 待修改 6：将新建 Agent 改为“基础创建 + 高级设置”

**优先级：P1**

当前新建 Agent 一页同时出现名称、模型、执行轮数、四项上下文压缩、系统提示词和三类能力。信息完整，但首次用户要先理解很多运行参数，才能得到第一个可用 Agent。

建议默认只展示：

- 名称与一句任务说明
- 模型
- “从模板开始”或“从空白开始”
- 系统提示词
- 能力绑定

将最大轮数、自动压缩、触发比例、保留轮数、摘要长度收进“高级运行设置”，使用推荐默认值。高级区应有“适合长对话”“适合复杂工具任务”等结果导向提示，少用 Token 参数解释作为第一层文案。

## 待修改 7：给新建 Agent 增加模板和配置完成度

**优先级：P1**

空白配置适合开发者，不适合第一次体验产品。建议提供至少三个本地模板：

- 对话分析助手：只用模型与提示词
- 文档整理助手：模型 + 文件读取 + 对应 Skill
- 本地任务助手：模型 + 时间工具，明确提示其他工具需审批

模板卡需展示：用途、启用能力、风险等级和可修改项。创建表单底部增加“配置检查”：模型可用、提示词已填写、能力数、风险能力数。保存按钮旁显示“可以开始对话”或“仍缺少模型配置”。

## 待修改 8：调整侧栏的信息架构，区分“工作”和“配置”

**优先级：P1**

当前聊天、Agent、模型、工具、MCP、Skills、运行记录和评测都以同等层级出现。对用户而言，“聊天”和“模型管理”的频率、目标完全不同。

建议保持现有八个地址，但视觉分组为：

- **工作空间**：聊天、运行记录、评测
- **Agent 配置**：Agent、模型、工具、MCP、Skills
- **帮助**：本地用户与使用指南

在窄栏保留图标、名称、焦点样式和悬浮提示。当前窄栏的图标加文字可继续使用，但“Agent”最好改为“Agent 配置”，避免和正在对话的 Agent 混淆。

## 待修改 9：把 Agent 列表卡片从“资源统计”改成“可用性概览”

**优先级：P1**

当前卡片能看出工具、Skills、MCP 数量，但无法一眼判断这个 Agent 适合什么任务、现在能否运行、是否存在风险能力。

每张卡片应优先显示：

- 一句用途说明；缺失时显示“尚未填写用途”，并在编辑入口提示补充。
- 状态：可用、模型不可用、能力已停用、需要检查。
- 能力摘要，例如“2 个只读工具 · 1 个写入工具需确认”。
- 最近一次运行结果和时间。

资源数量可以保留为次级信息。默认 Agent 的标签也应说明“新会话默认使用”，避免用户误解为唯一可用 Agent。

## 待修改 10：将运行记录列表改为“先结论，后明细”

**优先级：P1**

七列表格适合后台排查，不适合日常回看。窄宽度下，状态、模型、时间等列会挤压错误摘要，用户看不到最需要的信息。

建议：

- 桌面端保留表格，但默认列只留状态、Agent、耗时、成本/Token、开始时间。
- 失败原因在状态下方显示一行摘要，并加“修复配置”快捷入口。
- 手机和窄栏切换成可点击的运行卡片，不横向挤压表格。
- 筛选条件显示为可移除标签，结果区顶部显示“8 次运行，其中 3 次失败”。

## 待修改 11：运行详情的失败状态要给出下一步

**优先级：P1**

当前运行详情准确记录了“模型调用 0、工具执行 0、结束原因”，但失败原因下面没有能帮助用户修复的动作。

将首屏改为“结果摘要卡”：

- 成功：最终回答摘要、工具步骤数、耗时、Token 与“查看完整过程”。
- 失败：失败阶段、可读原因、主按钮“检查模型配置”或“编辑 Agent”、次按钮“复制诊断摘要”。
- 已取消：说明已完成的步骤和是否保留部分回答。

时间线保留为第二屏。它是调试证据，不应抢走结果与下一步操作的位置。

## 待修改 12：统一术语与风险提示的层级

**优先级：P2**

页面同时使用“Agent”“Skills”“MCP Server”“内置工具”“能力绑定”等术语。面对开发者可以保留英文标准名，但应在首次出现时固定解释，后续不重复写长段说明。

建议建立一套短标签：

- Agent：任务角色
- Skill：做事方法
- 工具：可执行操作
- MCP：外部工具连接

风险提示只在选择或审批高风险能力时出现。一般列表页不要持续显示大段安全文字，以免淹没主任务。

## 推荐实施顺序

先完成待修改 1、3、4、5。它们直接影响用户能否开始任务、是否理解执行过程、是否放心授权。之后做待修改 6、7、8，降低首次配置成本。最后优化运行列表和文案一致性。

## 审查限制

本次基于当前本地运行页面的实际查看完成；已查看失败状态和配置表单。未验证模型正常回答、工具执行成功、审批、键盘全流程和不同断点下的动态状态，因此这些交互在修改后仍需单独走查。
